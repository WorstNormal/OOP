# Snake Game (JavaFX)

Подробное описание учебного проекта по ООП: как устроен код, как запустить приложение, как работает игровой цикл, какие объектно-ориентированные принципы применены, и как расширять проект дальше.

## 1. Что это за проект

Это настольная игра Snake на Java + JavaFX.

В проекте есть:
- игрок (зеленая змейка),
- робот-змейка (синяя),
- еда, препятствия, поле,
- таймер игрового цикла,
- рендеринг на Canvas,
- модульные тесты на JUnit 5,
- проверка стиля и отчеты покрытия через Gradle.

Текущая точка входа приложения: `ru.nsu.gaev.snake.Main`.

## 2. Стек и инструменты

- Java
- JavaFX 20.0.2
- Gradle (через wrapper: `gradlew`, `gradlew.bat`)
- JUnit Jupiter 5.10
- JaCoCo
- Checkstyle

Настройки сборки находятся в `build.gradle`.

## 3. Структура проекта

Ключевые директории:

- `src/main/java/ru/nsu/gaev/snake` — основной код игры
- `src/main/resources/ru/nsu/gaev/snake` — FXML-разметка интерфейса

Основные пакеты:

- `view` — отрисовка состояния игры

## 6. Высокоуровневая архитектура (MVC-подход)

Проект логически разделен на три слоя.

### 6.1. Model

Содержит все игровые сущности и правила:
- `GameField` — агрегирует состояние матча и применяет правила,
- `Snake` и `RobotSnake` — змейки,
- `Food`, `Obstacle`, `Point`, `Level`, `Direction`,
- `RobotStrategy` и реализации (`GreedyStrategy`, `RandomStrategy`).

### 6.2. View

- `GameRenderer` рисует текущее состояние на `Canvas`.

### 6.3. Controller

- `GameController` связывает UI и модель,
- управляет циклом `AnimationTimer`,
- обрабатывает ввод с клавиатуры,
- обновляет `Label` со счетом/уровнем.

## 7. Пошаговый жизненный цикл программы

Ниже описан реальный порядок выполнения кода.

### Шаг 1. Запуск JavaFX приложения

Класс `ru.nsu.gaev.snake.Main` вызывает `launch()`, после чего JavaFX вызывает метод `start(Stage stage)`.

### Шаг 2. Загрузка FXML

`FXMLLoader` читает `game_view.fxml`, создается граф сцены и контроллер `GameController`.

### Шаг 3. Инициализация контроллера

В `GameController.initialize()`:

- вычисляется размер сетки по размеру Canvas и `CELL_SIZE`,
- создается первый уровень,
- создается `GameField`,
- добавляется робот-змейка со стратегией `GreedyStrategy`,
- создается `GameRenderer`,
- запускается `AnimationTimer`.

### Шаг 4. Игровой тик

На каждом тике (с учетом `tickDurationNs`):

- вызывается `gameField.update()`,
- вызывается `updateUI()` и отрисовка,
- проверяются флаги завершения игры.

### Шаг 5. Конец игры

Если выполнено одно из условий (`gameOver`, `gameWon`, `gameDraw`), таймер останавливается и отображается финальный статус.

## 8. Внутренняя логика `GameField`

`GameField` — центральный класс игровой логики.

### 8.1. Что хранит

- размеры поля,
- игрока,
- список роботов,
- список еды,
- список препятствий,
- текущий уровень,
- счет,
- флаги состояния игры.

### 8.2. Метод `update()`

`update()` выполняет одну итерацию правил:

1. Если игра не стартовала или уже завершена, метод сразу возвращается.
2. Двигается игрок.
3. Для каждого живого робота вызывается выбор следующего хода и движение.
4. Проверяются столкновения.
5. Проверяется поедание еды.
6. Проверяется достижение цели уровня.

### 8.3. Столкновения

Обрабатываются сценарии:

- игрок со стеной,
- игрок с собственным телом,
- игрок с препятствием,
- игрок с роботом,
- робот со стеной,
- робот с собой,
- робот с препятствием,
- head-to-head (возможна ничья).

### 8.4. Еда и счет

- при поедании игроком: змейка растет, счет увеличивается,
- при поедании роботом: робот растет,
- съеденная еда удаляется, на поле спавнится новая.

## 9. Как работает змейка (`Snake`)

`Snake` — базовая реализация поведения змеи.

### 9.1. Состояние

- `LinkedList<Point> body` — сегменты тела,
- `currentDirection` и `nextDirection`,
- `segmentsToGrow` — сколько сегментов добавить,
- `alive` — жива ли змейка.

### 9.2. Движение

Метод `move()`:

1. Проверяет, что змейка жива.
2. Фиксирует новое направление (`currentDirection = nextDirection`).
3. Считает новую голову (`head + dx/dy`).
4. Добавляет голову в начало списка.
5. Если есть рост (`segmentsToGrow > 0`), хвост не удаляется.
6. Иначе удаляется последний сегмент хвоста.

### 9.3. Запрет разворота

`setNextDirection()` не позволяет развернуться на 180 градусов, если длина больше 1.

## 10. Роботы и стратегии ИИ

### 10.1. `RobotSnake`

Наследуется от `Snake` и добавляет ссылку на `RobotStrategy`.

### 10.2. Контракт стратегии

`RobotStrategy` задает метод:

`Direction chooseNextDirection(RobotSnake robot, GameField field)`

Это позволяет менять алгоритм без изменения кода `RobotSnake`.

### 10.3. `GreedyStrategy`

- находит ближайшую еду по Манхэттенскому расстоянию,
- запускает BFS по клеткам,
- возвращает первое направление кратчайшего пути,
- если путь не найден, использует fallback (вперед/влево/вправо).

### 10.4. `RandomStrategy`

- проверяет безопасные направления,
- случайно выбирает одно из безопасных,
- если безопасных нет, оставляет текущее направление.

## 11. Отрисовка (`GameRenderer`)

`GameRenderer` не хранит игровую логику, только отображает `GameField`.

Рисует:

- фон,
- сетку,
- еду,
- препятствия,
- игрока,
- роботов,
- стартовое сообщение до начала движения.

Цвета живых и мертвых змеек различаются, чтобы визуально показать состояние.

## 12. Роль FXML и контроллера

В `game_view.fxml` описаны элементы интерфейса:

- верхняя панель (`HBox`) со счетом, уровнем и кнопкой правил,
- центральный `Canvas` для игрового поля,
- обработка клавиш через `onKeyPressed="#handleKeyPressed"`.

Контроллер связывается с элементами через `@FXML` поля.

## 13. Принципы ООП в проекте

Ниже перечислены принципы с привязкой к коду.

### 13.1. Инкапсуляция

- Состояние змейки и поля инкапсулировано в классах `Snake` и `GameField`.
- Изменения проходят через методы (`move`, `eat`, `kill`, `update`, `addRobot`).

### 13.2. Наследование

- `RobotSnake extends Snake`.
- Базовая логика движения переиспользуется, а поведение расширяется стратегией.

### 13.3. Полиморфизм

- `RobotSnake` работает с `RobotStrategy` как с интерфейсом.
- Можно подставлять любую стратегию (`GreedyStrategy`, `RandomStrategy`, пользовательские).

### 13.4. Абстракция

- Интерфейс `RobotStrategy` абстрагирует способ выбора хода.
- Интерфейс `GameObject` задает общую идею объекта с позицией.

### 13.5. Композиция

- `GameField` композиционно содержит игроков, роботов, еду и препятствия.
- `GameController` содержит модель и рендерер.

### 13.6. Иммутабельность value-объектов

- `Point`, `Food`, `Obstacle`, `Level` реализованы как `record`.
- Это делает данные компактными и безопасными для сравнения/передачи.

## 14. SOLID (краткая оценка)

- S (Single Responsibility): в целом соблюдается по слоям, но `GameField` большой и может быть дополнительно декомпозирован.
- O (Open/Closed): хорошо соблюдается для ИИ-стратегий.
- L (Liskov): `RobotSnake` корректно подставим как `Snake` в базовой логике.
- I (Interface Segregation): интерфейсы узкие и целевые (`RobotStrategy`, `GameObject`).
- D (Dependency Inversion): частично соблюдается (зависимость на `RobotStrategy`), но есть прямые `new` в контроллере.

## 15. Тестирование

Тесты покрывают базовые сценарии модели и стратегий.

Примеры:

- `SnakeTest` — движение, рост, самостолкновение,
- `GameFieldTest` — инициализация, столкновения со стеной/препятствием,
- `GreedyStrategyTest` — выбор направления роботом,
- `ModelTest` — `Point`, `Direction`, `Food`, `Level`, `Obstacle`, `RobotSnake`, `RandomStrategy`.

Команда запуска: `./gradlew test` или `.\gradlew.bat test`.

## 16. Практическое расширение проекта

Что можно добавить без ломки архитектуры:

1. Новые типы еды

- добавить значения в `FoodType`,
- обработать эффекты (скорость, бонусы, штрафы).

2. Новые стратегии ИИ

- создать класс, реализующий `RobotStrategy`,
- передать его в `RobotSnake` при создании.

3. Несколько уровней

- хранить список `Level`,
- переключать уровень при достижении порога,
- менять скорость, количество еды, препятствия.

4. Пауза/рестарт/меню

- добавить элементы в FXML,
- обработчики в `GameController`.

5. Улучшение доменной модели

- выделить отдельные сервисы столкновений/спавна,
- сделать неизменяемые представления списков наружу.

## 17. Известные особенности текущей реализации

- Победа по очкам фактически недостижима в текущем `initialize()`, потому что `targetScore = Integer.MAX_VALUE`.
- Завершение игры чаще наступает через столкновения (проигрыш/выигрыш/ничья), а не через целевой счет.
- В корне проекта есть отдельный `ru.nsu.gaev.Main` (демо-класс), но приложение Snake запускается через `ru.nsu.gaev.snake.Main`.
